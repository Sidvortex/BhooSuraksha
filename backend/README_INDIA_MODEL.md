# The India-Wide Model

This is the second trained model in this project, alongside the original
NER rainfall+slope model (`model.py`). It answers a different question and
was built from different, real data — this doc explains exactly what it is,
where the data came from, how it was built, and what it can't do.

## Data source

**NASA Global Landslide Catalog (GLC)**, compiled by NASA Goddard Space
Flight Center from news reports, disaster databases, and scientific sources
(Kirschbaum et al. 2010, *"A global landslide catalog for hazard
applications: method, results, and limitations"*, Natural Hazards 52,
561-575). The full catalog covers 1970-2019 and is public domain
(data.gov / data.humdata.org).

`backend/training/india_landslide_events.csv` is the India subset of that
catalog: **1,265 real, individually recorded landslide events**, each with
a date, location (lat/lon), state, landslide category/trigger/size, and
fatality count. `backend/training/nasa_glc_raw.csv` is the full global
catalog (11,033 events) it was filtered from, kept for reference.

This is a fundamentally different kind of data from the NER model's
rainfall/slope time series: it's a record of *where and when landslides
were reported*, not continuous physical sensor readings.

## Why a second model instead of retraining the first one

The NER model needs rainfall (1/3/7/30-day sums) and slope for every
training row. GLC doesn't have those — it has locations and dates. Rather
than fabricate rainfall/slope values for 1,265 events (which would just be
guessing), this model uses what the data actually supports: the real
seasonal and geographic pattern in *where* landslides get reported across
India.

## How it was built (`backend/training/train_india_model.py`)

1. **Positives**: the 1,265 real GLC events, each labeled `landslide=1`,
   with `month` extracted from the event date.
2. **Negatives (pseudo-absence sampling)**: for every real event, one
   synthetic "no recorded landslide" point is generated by jittering that
   event's coordinates by 0.3-1.5 degrees (roughly 30-150 km) and assigning
   an unrelated random month. This is a standard technique in landslide
   susceptibility modeling — see the caveat below on what it does and
   doesn't mean.
3. **Features**: `latitude`, `longitude`, `month_sin`/`month_cos` (cyclical
   encoding of season), and `state_freq` (that state's share of all
   recorded events, computed from the training split only, to avoid
   leaking test labels into a feature).
4. **Model**: `RandomForestClassifier(n_estimators=300, max_depth=8,
   class_weight="balanced")`, an 80/20 stratified train/test split.

Real hold-out results (regenerated every time you run the script — see
`backend/models/india_model_metrics.json`):

| Metric | Value |
|---|---|
| Accuracy | 0.771 |
| Precision | 0.719 |
| Recall | 0.889 |
| F1 | 0.795 |
| ROC-AUC | 0.841 |

## What it can answer

Given a latitude, longitude, and date, `/api/predict/india` returns a
probability, risk level, the nearest state (approximate nearest-centroid
labeling — see `zones.py`'s equivalent caveat), and which of its three
inputs (season, state history, location) mattered most for that specific
call.

## Important limitations — read before trusting this for anything real

- **Reporting bias, not true absence.** GLC is built from news and report
  sources. A place with no recorded event might genuinely be safe, or it
  might just be remote, sparsely populated, or under-covered by the media
  the catalog draws from. The "negative" class here means "no recorded
  report," not "verified safe."
- **No physical terrain or weather data.** Unlike the NER model, this one
  has no rainfall, slope, soil, or geology inputs. It cannot tell you "it's
  raining heavily right now, is this slope at risk" — it can only tell you
  "historically, this region and season have/haven't seen reported events."
- **State-level frequency can dominate.** `state_freq` is a strong,
  coarse-grained feature. It captures real regional variation (Uttarakhand,
  Kashmir, and Himachal Pradesh account for a large share of GLC's India
  events) but can't distinguish a specific risky slope from a specific
  safe one within the same state.
- **Coverage period is 2007-2016.** It doesn't reflect any changes in land
  use, construction, or climate patterns since then.
- **Nothing here is validated for operational disaster response.** Treat
  it as a demonstration of what's learnable from open event data, not a
  certified hazard model.

## Retraining it yourself

```bash
cd backend/training
pip install -r ../requirements.txt
python train_india_model.py
```

This regenerates `backend/models/india_risk_model.pkl`,
`india_state_freq.json`, and `india_model_metrics.json` from the CSV in
this folder. If you have a better India-wide event dataset (e.g. from GSI
Bhukosh, ISRO NRSC, or a state disaster management department), swap it in
— keep the same output columns (`latitude`, `longitude`, `event_date`,
`admin_division_name`) or adjust the loading code in
`train_india_model.py` to match.
